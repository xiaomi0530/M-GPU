# Nexys A7-100T VGA 接入

目标器件：`xc7a100tcsg324-1`。板级信息来自所提供的 Nexys A7 Reference
Manual 第 13、18、21、22 页，引脚电气标准另与 Digilent 官方
[Master XDC](https://github.com/Digilent/digilent-xdc/blob/master/Nexys-A7-100T-Master.xdc) 核对。

## 文件和原有代码边界

- `MGPU.srcs/sources_1/new/vga.v`：完整扫描时序、读地址、RGB332 到 RGB444 转换。
- `MGPU.srcs/sources_1/new/top.v`：板级时钟、复位、按键、三阶段演示和正方体旋转计算。
- `MGPU.srcs/constrs_1/new/nexys_a7_vga.xdc`：时钟和实际引脚约束。
- `mgpu.v`：仅在端口列表末尾追加 VGA 接口，在 `endmodule` 前追加有明确标记的
  独立读取逻辑和 VGA 实例；原有 GPU 实现、framebuffer 声明和写端口保持原样。
- `MGPU.xpr`：加入新 RTL/XDC，综合顶层设为 `top`，原仿真顶层仍是 `mgpu_tb`。

GPU 仍然存储 **640×480×8 bit RGB332**。VGA 每次直接读它，不拷贝整帧，也不等待
`gpu_done`。GPU 写入后，扫描再次经过对应像素时即可看到新值，通常最多等待约一帧。
这是单缓冲实时显示，绘制过程中可能看到逐步形成的图形或撕裂。

## 时钟、读取和颜色

板载时钟为 100 MHz。VGA 使用该时钟，每四拍输出一个像素，即 25 MHz 像素速率。
你的 GPU 中保留的组合除法等长路径未流水化，100 MHz 初次布局检查得到约
−87 ns 的最差余量。因此 `top.v` 通过自由运行的 16 分频计数器和专用 `BUFG`
提供 **6.25 MHz GPU 时钟**，不更改原有运算逻辑。XDC 对它设置了真实的生成时钟，
没有通过 false path 或 multicycle 隐藏 GPU 运算路径。

framebuffer 使用 GPU 时钟写入、100 MHz 时钟同步读取，供 Vivado 推断双端口块 RAM。
板级复位在两个时钟域分别经过四级同步，断言和释放都只在对应时钟边沿生效，
避免异步按键直接改变 RAM 端口使能。配置后的寄存器初值保证无需按键也能启动。
VGA 时钟和复位是 `mgpu` 新增的 `vga_clk`、`vga_rst` 输入。以后在其他顶层接 VGA 时，
也要连接这两个输入；固定显示模式要求保留默认 `640×480` 帧缓冲尺寸。

每个像素四拍：

1. phase 0：读端口采样 `fb_addr`，数据寄存到 `vga_fb_data`。
2. phase 1：VGA 采样该数据，同时更新与它对应的 HS、VS、RGB。
3. phase 2：保持输出。
4. phase 3：保持输出并推进下一个扫描坐标。

有效区内才发起读取，消隐区输出黑色。并发读写同一地址时，本次读出的颜色可能是
旧值或受 RAM 碰撞行为影响；写入稳定后下一次扫描会读到新值。没有双缓冲保证整帧原子更新。

颜色扩展仅发生在 `vga.v`：

```verilog
R4 = {R3, R3[2]};
G4 = {G3, G3[2]};
B4 = {B2, B2};
```

这样全黑仍是 0、最大亮度仍是 15，实际颜色数量仍然是 RGB332 的 256 色。

## 扫描参数

采用手册 Figure 8.1.3 的 25 MHz 示例；其中垂直后沿为 **29 行**，总计 **521 行**，
不是常见 25.175 MHz 模式的 525 行。

| 方向 | 有效区 | 前沿 | 同步脉冲 | 后沿 | 总计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 水平（像素） | 640 | 16 | 96 | 48 | 800 |
| 垂直（行） | 480 | 10 | 2 | 29 | 521 |

HS、VS 低有效；行频 31.25 kHz，帧率约 59.98 Hz。

## 使用

重新打开 `MGPU.xpr`，确认设计顶层为 `top`。若 Vivado 已经打开工程，需重新载入磁盘上的
工程配置，避免继续使用内存里旧的文件列表。运行综合、实现和生成 bitstream 后通过 Hardware
Manager 下载到 Nexys A7-100T；接上 VGA 显示器。

- 下载完成后依次显示 **中心校准图 → 原 RGB 大三角形 → 持续旋转的正方体**。
  前两幅图绘制完成后各停留 4 秒，随后自动切换；进入正方体后一直循环旋转。
- 校准图包含距四边对称的白色外框、160×160 居中方框、中心十字和黄色中心点。
  它关于 `(319.5,239.5)` 对称，便于观察屏幕整体偏移和裁切。
- 按 **BTNU（上键）**：跳过当前已经画完的画面的剩余停留时间；绘制期间的按键忽略。
- 按 **CPU RESET**：从校准图阶段重新开始。原 framebuffer 无硬件清屏接口，
  控制器会通过两个黑色三角形完成全屏清除，然后画校准图。
- 按键在 GPU 时钟域同步并消抖，默认约 10.5 ms；长按只产生一次提交。
- 演示源和所有顶点计算在 `top.v` 中，未来用 CPU 命令接口替换即可。

### 修改停留时间与理解正方体计算

`top.v` 顶部的 `STAGE_HOLD_MS=4000` 控制前两阶段的完整画面停留时间，
`CUBE_HOLD_MS=40` 控制每幅正方体画完后的额外停留。实际动画帧周期还包含擦除、
GPU 光栅化和 FIFO 排空时间，因此 40 ms 不代表能达到 25 FPS。

正方体默认八个顶点坐标为 `(±96,±96,±96)`，边长为原版的两倍。
`CUBE_HALF_SIZE=96` 控制半边长，建议取 32～128；局部清除范围随它自动调整。
配色统一为 `CUBE_LIGHT=8'h9F`、`CUBE_MID=8'h57`、`CUBE_DARK=8'h2E` 三档冰蓝色，
分别用于前后面、左右面和底面，以明暗区分朝向。每帧绕 Y 轴增加 5.625°，64 帧转一圈，
另绕 X 轴固定倾斜约 30°。正弦/余弦使用 Q8 查表，旋转使用整数乘加和算术右移。
正交投影把旋转后的 X/Y 平移至屏幕中心，不使用浮点数或仿真专用三角函数。

六个面各拆成两个三角形。根据旋转后法线是否朝向观察者跳过背面；凸正方体的可见面
不会互相遮挡，因此此演示不要求增加 depth buffer。整数投影后面积为零的三角形也会
被跳过，避免原光栅器除以零。

阶段切换使用全屏黑色三角形清除；默认大小的正方体后续帧只清除 `[176..464]×[80..400]` 区域，
以减少绘制开销并防止拖影。GPU、Shader、VGA、RGB332 格式和 framebuffer 均未为此修改。
单缓冲实时扫描会暴露擦除和重画过程，动画可能闪烁；当前实现没有双缓冲。
放大后物体面积约为原来的四倍，GPU 要处理的像素更多，实际动画帧率会降低。

顶层 `clear_color` 固定接黑色。原有 `initial` 中用输入信号初始化 RAM 的写法会被 Vivado
警告为非常量初始化；该代码按要求保留。不能把此接口当作可动态使用的硬件清屏功能。
构建脚本会检查实际映射的 framebuffer BRAM 的全部 INIT/INITP 数据为零，
检查通过才继续生成 bitstream；结果记录在 `out/vga_current/framebuffer_init.rpt`。

| 板级端口 | FPGA 引脚 |
| --- | --- |
| CLK100MHZ | E3 |
| CPU_RESETN / BTNU | C12 / M18 |
| VGA_R[0..3] | A3, B4, C5, A4 |
| VGA_G[0..3] | C6, A5, B6, A6 |
| VGA_B[0..3] | B7, C7, D7, D8 |
| VGA_HS / VGA_VS | B11 / B12 |

所有上述端口使用 LVCMOS33。输出端设置 10 ns 的寄存器到引脚布线预算；这不是显示器
提供的外部 setup/hold 指标，因为 VGA 接口没有转发像素时钟。

## 验证与构建

Icarus Verilog 测试：

```powershell
powershell -ExecutionPolicy Bypass -File tools/test_vga.ps1
```

包括完整帧的独立时序/读地址检查、全部 256 色、消隐、像素保持、中途复位、64 个角度及
回绕的独立实数几何对照、背面剔除、阶段停留、实际 GPU 三阶段绘制与 VGA 同时读取，
以及原 `mgpu_tb +DEMO` 回归。实际绘制测试会把画面保存到 `out/vga_current/*.hex`。
顶层功能仿真将 GPU 分频改为 /2 以缩短时间；硬件时序以默认 /16 的 Vivado 实现结果为准。
原始 testbench 未连接新 VGA 端口时，仍可单独验证 GPU；编译源列表需要包含 `vga.v`。

Vivado 独立构建（工程根目录执行）：

```powershell
& 'C:/Xilinx/2025.1/Vivado/bin/vivado.bat' -mode batch -source tools/build_vga.tcl
```

输出在 `out/vga_current/`，独立于原工程的 runs。脚本在 setup/hold 不通过时停止，不生成
宣称时序通过的 bitstream。测试输出单独存放，不覆盖已有 `out/framebuffer.hex/png`。

## 初次 VGA 接入验证（2026-09-22，三阶段演示加入前）

- VGA 独立测试通过：两帧、每帧 307200 次读取、全部 256 色、同步/消隐/像素保持和中途复位。
- GPU 与 VGA 联合测试通过：两次提交、128482 次 GPU 写入、921600 次实时读取。
- 原 `mgpu_tb +DEMO` 回归通过：78 个三角形、183328 个片元与等量写回，覆盖 FIFO 满反压。
- `mgpu.v` 原有模块主体按字节比较未改变；预先存在的 `shader.v` 空行改动保留。
- Vivado 2025.1 完成综合、布局、布线与 bitstream 生成；WNS **+1.630 ns**，WHS **+0.041 ns**，
  无失败的 setup/hold/pulse-width 端点，无无时钟或未约束的内部端点。
- DRC 无错误；剩余 25 条为原运算通路的 DSP 流水线建议，没有 RAM 异步控制告警。
- 实际 framebuffer 的 80 个 BRAM 共 11520 个 INIT/INITP 字段全部为零。
- 两个机械按键输入按异步输入处理，报告中的 2 个 `no_input_delay` 属于这两个有同步器的端口。
