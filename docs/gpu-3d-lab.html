01 / MODEL → WORLD → VIEW
顶点是位置，法线是方向
模型坐标描述物体自己的形状。模型矩阵 M 把它放进世界，观察矩阵 V 把世界改写成摄像机的视角。矩阵乘法从右向左执行；绕自身原点旋转后再移动，与先移动再旋转不是一回事。
pmodel = [x, y, z, 1]ᵀ
pview = V · M · pmodel
本页：V = I，M = T(0,0,d) · Ry(θ) · Rx(φ)

Rx(φ) = [ 1   0       0      0 ]    Ry(θ) = [ cosθ  0  sinθ  0 ]
        [ 0  cosφ   −sinφ    0 ]            [  0    1   0    0 ]
        [ 0  sinφ    cosφ    0 ]            [−sinθ  0  cosθ  0 ]
        [ 0   0       0      1 ]            [  0    0   0    1 ]
位置的末尾是 1
齐次坐标中的 1 使平移矩阵能够改变位置。相机移到 C 时，观察变换先减去 C，再转换到相机基底。通常 V 是摄像机世界变换的逆。
法线不带平移
纯旋转下 N′=RN。一般非均匀缩放下，要用线性变换的逆转置再归一化，不能直接套位置矩阵。本页从旋转后边向量的叉积得到每面法线。



02 / VIEW → CLIP → NDC → SCREEN
近大远小来自一次除法
相似三角形给出图像平面位置 ximage = fx·x/z。相同的横向尺寸放到两倍远处，投影尺寸就减半。焦距变大，画面更放大，视场角更小。
H=480，W=640，aspect=W/H，s=cot(FOVy/2)
fx = (W/2)·s/aspect = (H/2)·s，fy=(H/2)·s
xs = W/2 + fx·xview/zview
ys = H/2 − fy·yview/zview
为了用一次矩阵乘法统一投影并保留裁剪信息，构造齐次坐标。令 A=f/(f−n)，B=−fn/(f−n)：
P = [ s/aspect  0  0  0 ]
    [    0     s  0  0 ]
    [    0     0  A  B ]
    [    0     0  1  0 ]

[xc,yc,zc,wc]ᵀ = P · [xview,yview,zview,1]ᵀ
wc = zview
NDC = (xc/wc, yc/wc, zc/wc)  ← 先裁剪，再做这一步！
xs = (xndc+1)·W/2，ys = (1−yndc)·H/2
d = zndc = A+B/zview
代入 zview=n 得到 d=0；代入 zview=f 得到 d=1。这解释了为什么深度不是简单的“距离除以最远距离”。NDC 边界 +1 对应视口边界 W，而不是最后一个像素中心 W−0.5；覆盖测试采样在 (i+0.5,j+0.5)。
W 不是第四个空间方向。它让投影可先表示为线性齐次变换，再通过除法恢复三维坐标。正交投影一般令 w=1，因此没有随距离缩小的效果。



03 / CLIP BEFORE DIVIDE
裁剪的是三角形，不是分别夹紧三个顶点
裁剪空间中的合法区域由六个线性半空间构成。这时即使原始顶点 w≤0，也不必先执行危险的除法。
左：xc+wc ≥ 0     右：wc−xc ≥ 0
下：yc+wc ≥ 0     上：wc−yc ≥ 0
近：zc ≥ 0        远：wc−zc ≥ 0
对每个平面，沿多边形的边走一圈。设平面函数为 F，边端点为 U、V。当两端一内一外时，求交点：
t = F(U) / [F(U)−F(V)]
Qclip = (1−t)·Uclip + t·Vclip
Qattribute = (1−t)·Uattribute + t·Vattribute
内→内保留末端；内→外保留交点；外→内保留交点及末端；外→外不输出。依次处理六个平面，最后对凸多边形做扇形三角剖分：(v0,v1,v2)、(v0,v2,v3)…。原始 UV 等 smooth 属性随同一参数 t 插值，之后才为新顶点计算 UV/w。
点击“穿过近裁剪面”，调整 n：顶点可能被删除，交点会出现，裁剪结果可能变成两个以上三角形。直接丢弃整条跨面的三角形会产生空洞；直接夹紧顶点坐标会改变形状。



04 / TRIANGLE → FRAGMENTS
边函数回答：这个像素中心在三角形里吗？
E(A,B,P) = (Bx−Ax)(Py−Ay) − (By−Ay)(Px−Ax)
S = E(A,B,C)
λ0 = E(B,C,P)/S
λ1 = E(C,A,P)/S
λ2 = E(A,B,P)/S
λ0+λ1+λ2 = 1
把顶点顺序规范到 S>0 后，三个边函数非负表示在内部。S=0 是退化三角形，应直接结束，不能继续除以面积。遍历包围盒中每个像素中心 P=(i+0.5,j+0.5)，即可得到片元。
相邻三角形共享边时，不能让双方同时包含边界。本页采用屏幕 Y 向下、S>0 的 top-left 约定：边界只在 dy<0 或 dy=0 且 dx>0 时包含。硬件通常用定点子像素坐标和精确整数边函数，避免浮点舍入破坏共享边一致性。
向右一步：E(x+1,y) = E(x,y) − (By−Ay)
向下一步：E(x,y+1) = E(x,y) + (Bx−Ax)

任意屏幕线性属性：a(x,y)=a起点+Δax·Δx+Δay·Δy
这就是你现在 rasterizer 的增量遍历思路：setup 阶段做乘除法，扫描阶段主要做加法。点击画面或输入像素坐标，可看到该样本的 λ、深度与 UV。外部样本不会因为“颜色为黑”而被误认为有效片元。



05 / PERSPECTIVE-CORRECT INTERPOLATION
为什么棋盘格需要插值 u/w，而不是直接插值 u？
投影中的除法是非线性的。屏幕上走了一半，不代表三维边上也走了一半。设屏幕重心坐标为 λ，三维属性的有效权重应为：
q = λ0/w0 + λ1/w1 + λ2/w2
βi = (λi/wi) / q
a = β0·a0 + β1·a1 + β2·a2
  = [λ0·a0/w0 + λ1·a1/w1 + λ2·a2/w2] / q
所以 setup 为每个顶点计算 1/w、u/w、v/w；光栅器线性插值这些量；恢复 UV 时共用一次 q 的倒数。点击“透视插值对比”，开关“透视正确 UV 插值”：斜面上的格子大小变化与两个三角形接缝最容易暴露错误。
一维例子：w0=1，w1=4，u0=0，u1=1
屏幕中点 λ0=λ1=0.5：
普通插值 u = 0.5
透视正确 u = (0.5·0/1 + 0.5·1/4)/(0.5/1+0.5/4) = 0.2
不是所有属性都要再次除 q。顶点经过投影的深度 d=zc/wc 在屏幕空间线性插值；每面固定颜色/法线不需要插值；UV、观察空间位置等通常需要透视校正。不要把观察空间 z 和深度 d 混为一谈。
本页棋盘纹理是 floor(8u) 与 floor(8v) 的奇偶异或，没有外部图片读取。硬件可先用同样的程序化纹理验证 UV，再替换成 BRAM 最近邻采样。教学画面未做纹理抗锯齿，远处细格可能出现锯齿或摩尔纹。



06 / SHADE → TEST → WRITE
方向决定亮度，深度决定谁被看见
每面 Lambert 光照
N = normalize[(B−A) × (C−A)]
L = 单位向量，表面指向光源
D = max(0, N·L)
I = 0.22 + 0.78·D
Cout = clamp(Cbase·I)
演示不做背面剔除，立方体各面顶点顺序保证法线向外；光照按原始面朝向计算，背面不会自动翻转法线。拖动光源角度只改变颜色，不改变形状。
RGB332 开关在光照后量化到 R=8、G=8、B=4 个等级；亮度台阶来自量化。本页用线性数值颜色演示，未建模显示器伽马。
逐片元深度比较
dnew = λ0·d0 + λ1·d1 + λ2·d2
if (dnew < zbuffer[x,y]):
    zbuffer[x,y] = dnew
    framebuffer[x,y] = shadedColor
本页深度清为 1，并使用 LESS；恰好在远面的 d=1 不会通过。关闭深度测试时，最后提交的片元覆盖前面的片元；开启后，非共面表面的遮挡不依赖提交顺序。相等深度仍由比较规则与先后顺序决定。
真实 GPU 在满足条件时可以把深度测试提前，减少被遮挡片元的着色工作。透明混合、shader 改写深度或 discard 会带来额外规则；本页只处理不透明片元。



07 / MAP THE MATH TO YOUR MGPU
先扩展前端，再扩展片元属性
三维命令→顶点变换→六平面裁剪→透视除法 / 视口→现有光栅器→片元 FIFO→shader / 深度写回
模块输入 → 输出第一版硬件实现
vertex_transform有符号 XYZ → 齐次 XYZW共享 DSP，多周期乘加；矩阵按命令锁存
clipper三角形 → 裁剪多边形 → 三角形小顶点缓存 + FSM + 共享除法器
perspective / viewportXYZW → 屏幕 XY、d、1/w先计算倒数，再乘；保存子像素精度
triangle setup屏幕顶点 → 边函数 / 属性梯度面积零检测、包围盒、梯度除法
rasterizer边函数 / 梯度 → XY、d、u/w、v/w、1/w增量加法 + top-left 覆盖 + valid/ready
shader片元属性 → 颜色先每面光照，再纹理与逐片元光照
写回单元XY、深度、颜色 → 存储更新深度读改写、同地址冒险处理、写入仲裁


定点实现中的四个边界
  1. 负坐标：裁剪、变换必须保留 signed；不能先截成 10 位无符号数再判断是否越界。
  2. 中间位宽：16×16 有符号乘法先保存 32 位，多个乘积相加还要扩位；定好小数位后再舍入、饱和。
  3. 反压：每级在 valid=1 且 ready=0 时保留数据。裁剪可能让一个三角形产生多条输出命令。
  4. 完成：输入处理结束不等于绘制完成；必须等所有裁剪输出、FIFO、shader、深度请求和颜色写回排空。


640×480 RGB332 颜色缓冲需要 300 KiB；16 位深度缓冲另需 600 KiB。这里仅计算存储需求，不假设你的 FPGA 片上资源能容纳它们；应检查综合资源，再决定降低深度缓冲分辨率、分块或使用外部存储。


适合边做边学的顺序
  1. 三维单三角形，固定颜色，限制在视锥内：验证旋转与透视。
  2. 加入裁剪：验证一个输入产生零个、一个或多个输出。
  3. 深度缓冲：验证相交三角形、交换提交顺序结果不变。
  4. 每面法线光照：旋转立方体，确认法线与顶点使用同一旋转。
  5. 透视正确 UV 与纹理：对比斜面棋盘格。
  6. 在正确性测试稳定后再做流水化、多片元并行和性能统计。
本页是浮点数学参考，不是周期精确 RTL 仿真，也不代表硬件吞吐或定点误差。接入 MGPU 时要增加定点参考模型，逐片元比对位置、深度与颜色；页面不会修改你的 Verilog。
