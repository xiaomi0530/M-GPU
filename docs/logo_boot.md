# 旧版黑底 Logo 开屏

当前开屏为 **MIDIYAS GPU / PRISM CORE 晶核启动**，整段约 **7 秒、420 个连续相位**，由 17 个运动组使用各自的 MVP 矩阵完成。青紫立体双翼围绕金色晶核，配合能量框、独立字母和 GPU 标签居中显示。前 3 个相位保留黑场，随后以比旧版放慢约 1.4 倍的节奏展示双翼汇聚、字母依次出现和 GPU 标签入位；后段 Logo 向屏幕中心收拢，只留下金色晶核。

第 372～419 相位是 48 帧奶龙入场：原版 B 模型从晶核所在位置逐渐展开，同时缓缓开始旋转。入场末帧的 MVP 和绘制顺序严格等于普通环绕相位 24，随后从相位 25 继续，避免静止 Logo 直接切到完整模型。继续使用 40 MHz GPU、目标 60 FPS 和双缓冲，不修改 GPU 核心。`LOGO_HOLD_MS=7000` 设置开屏最短时间，控制器同时等待最后相位完成显示；设为 `0` 可跳过整段开屏，直接从 `START_FRAME` 指定的奶龙环绕相位开始。

当前生成入口为 `tools/build_vertex_lab.py`，几何与运动定义位于 `tools/midiyas_logo.py`；详细设计、验证与最新比特流见 [README](../README.md)。下文保留早期位图压缩方案，其中“当前”及下载路径均为当时的历史记录。

开机顺序：Logo → 校准图 → 太空背景 → 卫星巡航。CPU_RESETN 重启整个顺序。Logo 完整绘制后默认停留 4 秒，参数 LOGO_HOLD_MS 可调整，BTNU 可跳过停留。

原始素材 logo.png 不改动。根据用户“扣掉白色部分，或者反色”的要求，使用内置 imagegen 生成黑底白字、保留蓝色环带的适配版本 assets/logo/black_logo.png。未采用整图反色；蓝色没有变成橙色。第一次带光晕的生成结果未用于最终素材。

最终图像编辑提示词要求：严格保留 MIDIYAS/GPU 字形、相对布局、环带与四角星；白色背景换为纯黑，深色文字换为白色；蓝/青环带保持蓝色；禁止发光、光晕、模糊、外部渐变。输入为用户 logo.png，使用内置 imagegen 而非 CLI。

## 清晰度与存储

- 裁掉素材外围留白，保持纵横比，主体缩放到 560×223 像素，放在 576×240 的黑底区域内；区域左上角 (32,120)，居中显示在 640×480 屏幕。
- 缩放使用 Lanczos，然后按原有 RGB332 量化。不改变 GPU/VGA 的像素格式。
- 逐像素量化结果不再经过有损三角网格拟合；连续同色水平像素压缩为 6399 条记录，每条 36 位，共 230364 位原始 ROM 数据。
- 每条记录由 top 解码为两个平面同色三角形，共 12798 条，加上启动清屏两条，总计 12800 条命令。
- 光栅器不能画零面积单行三角形，因此每条水平记录绘制两行高矩形，后续行覆盖前一行多画的部分；单像素宽记录临时扩成两像素宽，后续记录覆盖多画的列。右边和底边的黑色保护边保证最终画面精确还原，无越界。
- “无损”指相对于缩放后的 RGB332 图像逐像素相同，不代表能保留原始 RGB888 的全部色阶。

## 代码和预览

- top.v 中 logo_active 控制启动阶段；boot_logo_rom 使用同步读 BRAM，与原场景命令 ROM 分开。
- tools/logo_boot.py 可从 assets/logo/black_logo.png 重新生成压缩数据、预览和 top.v。依赖 numpy/Pillow，内部调用 tools/build_space_demo.py。
- tools/build_space_demo.py 再生成原太空演示时会自动接入已有 Logo，避免后续生成覆盖开屏功能。
- 预览：assets/logo/preview.png；真实 GPU 仿真导出：out/logo/actual.hex。
- 原始 GPU 核心、VGA 和时钟约束未修改。仍通过 GPU 三角形接口绘制，不直接绕过 framebuffer 写回。

当前下载文件：out/vga_current/nexys_a7_vga.bit，尚未实板验证。


## 验证结果

- 实际 GPU/VGA 仿真：12800 条 Logo 绘制命令，307200 像素与目标图逐像素一致；随后校准图与清除检查通过，共 916412 次写回、6306153 次实时扫描读取。
- 完整命令级测试通过 Logo、原演示和 32 帧卫星回绕，共 19018 条命令。
- Vivado 布线后时序通过：sys_clk WNS +1.057 ns，gpu_clk WNS +39.363 ns，最小 WHS +0.089 ns。BRAM 110/135（81.48%）。
- 核心文件哈希保持不变；重新生成得到完全一致的 top.v。
